# Grocery Demand Pulse — public deployment

## What is included
- `Grocery_Demand_Pulse.ipynb`: model-training notebook for Kaggle.
- `grocery_sales_updated_datewise.csv`: source sales dataset.
- `artifacts/sku_forecasts.csv`: forecast table used by the public API.
- `artifacts/`: evaluation and analysis outputs.
- `app.py`: FastAPI API; also serves `/dashboard`.
- `demand_model.pkl` and `legacy_main.py`: original model bundle and earlier API retained for reference; the public API uses the generated forecast CSV to avoid pickle-version compatibility problems.
- `inventory_dashboard.html`: dashboard.
- `requirements.txt`: deployment dependencies.
- `render.yaml`: Render deployment configuration.
- `vercel.json`: optional Vercel configuration.

## Important modelling note
The source sales CSV does not contain actual stock-on-hand records. The stockout endpoint therefore uses a simulated on-hand value when `on_hand` is omitted. Supply a real `on_hand` value to calculate risk from actual inventory.

The API serves forecasts already generated by the Kaggle notebook. The original `demand_model.pkl` is retained in this archive for reference, but is not loaded by the deployed API because serialized scikit-learn/pandas objects can fail across package versions. Re-run the notebook when you update the sales data, then replace `artifacts/sku_forecasts.csv` with the newly generated file and redeploy.

## Deploy publicly on Render (recommended)
1. Push this folder's contents to a GitHub repository.
2. In Render, choose **New → Blueprint** and connect that repository, or create a **Web Service**.
3. Use build command: `pip install -r requirements.txt`
4. Use start command: `uvicorn app:app --host 0.0.0.0 --port $PORT`
5. After deployment, your public URLs will be:
   - `https://YOUR-SERVICE.onrender.com/`
   - `https://YOUR-SERVICE.onrender.com/docs`
   - `https://YOUR-SERVICE.onrender.com/dashboard`

The free Render service may sleep after inactivity and take a short time to wake up.

## Optional Vercel deployment
Connect the repository to Vercel and deploy. The project includes `app.py` and `vercel.json`; Vercel's Python runtime packages FastAPI as a Function. Check the current Function size/runtime limits if you later add larger model files or heavier dependencies.

## Kaggle upload
1. Open Kaggle → Datasets → New Dataset.
2. Upload `grocery_sales_updated_datewise.csv`, `Grocery_Demand_Pulse.ipynb`, and the `artifacts` folder if you want to publish the generated outputs.
3. Alternatively, upload the complete `Grocery_Demand_Pulse_Public_Deploy.zip` as a dataset archive.
4. Create a Kaggle Notebook and attach this dataset using **Add Input**.
5. In the notebook, update `DATA_FILE` to the mounted Kaggle input path if needed, run all cells, and download the generated `demand_model.pkl` / `artifacts` from `/kaggle/working`.

Kaggle is the data and model-training workspace here, not the always-on public FastAPI host. Use Render or Vercel for the public API URL.
